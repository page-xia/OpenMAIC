# OpenMAIC 师生分离改造 + 课件运营后台 + MySQL 存储方案

## 一、目标与第一性原理

核心问题：现状把「内容生产」（上传 zip、AI 生成、模型/TTS 配置）和「内容消费」（上课学习）混在同一个学生浏览器里，且数据存在 IndexedDB/localStorage，无法集中运营。

改造后的模型：
- **老师端（运营后台）**：账号登录 → 创建课件（PPTX 上传 / AI 生成 / zip 导入 / 空白新建）→ 在线编辑（场景、幻灯片、讲课脚本、AI 老师）→ 预览 → 发布。系统设置（模型 Key、TTS 等）全部在后台页面配置，存 MySQL。
- **学生端**：只看到已发布课程库 → 进课堂学习。零配置、开箱即用，语音预生成即点即播。
- **MySQL 为服务端权威数据源**：课件文档、场景、媒体元数据、发布快照、教师账号、系统设置全部入库；媒体文件存磁盘（`data/courseware/`），数据库记元数据，API 流式播放。

用户未答复的决策项，按推荐项执行：① 同一 Next.js 服务、`/teacher/*` 路由分区（隔离体验、最小改造量）；② 教师账号体系（teachers 表 + cookie 会话，seed 首个管理员）；③ 四种创建方式全做（PPTX 为主入口）；④ 媒体磁盘 + MySQL 元数据。

## 二、数据库设计（新建库 `openmaic`，utf8mb4）

```sql
teachers        (id, username UNIQUE, password_hash /*node scrypt*/, display_name, role ENUM('admin','teacher'), created_at, updated_at)
courses         (id /*=stageId*/, teacher_id FK, title, description, language, style, cover_asset_id,
                 status ENUM('draft','published','archived') DEFAULT 'draft',
                 source ENUM('pptx','ai_generation','maic_zip','blank'),
                 stage_json JSON /*完整 Stage DSL 含 generatedAgentConfigs*/,
                 published_version INT DEFAULT 0, published_at, created_at, updated_at,
                 INDEX(teacher_id,status), INDEX(status,updated_at))
scenes          (id, course_id FK CASCADE, type ENUM('slide','quiz','interactive','pbl'), title,
                 sort_order, content_json JSON, actions_json JSON, whiteboards_json JSON, multi_agent_json JSON,
                 INDEX(course_id, sort_order))
assets          (id /*AssetRef pool id*/, course_id, kind ENUM('image','audio','video','poster','file'),
                 file_path /*data/courseware/...*/, mime_type, size_bytes, duration_sec,
                 origin ENUM('pptx_import','maic_zip','upload','generated','tts'), metadata JSON, created_at)
course_publications (id, course_id FK CASCADE, version INT, snapshot_json JSON /*{stage,scenes} 完整快照*/,
                 published_by, published_at, UNIQUE(course_id, version))
system_settings (setting_key PK, value_json JSON, updated_at, updated_by)
```

发布采用**快照冻结**：学生只读 `course_publications` 最新版，老师改草稿不影响在线学生；重新发布生成 version+1。

连接配置：`configs/db_config.yml`（db_type/host/port/db/user/pwd，用户已提供 127.0.0.1:3306 root/12345678）+ `.env` 的 `MYSQL_*` 变量（env 优先）。依赖只加 `mysql2`（纯 JS，Windows 无编译问题）；密码哈希用 node 内置 `crypto.scrypt`，不引 bcrypt。

## 三、总体架构

```
Next.js 单服务（:3000）
├─ middleware.ts：/teacher/* 与 /api/teacher/* 需教师会话（HMAC 签名 cookie，复用 access-token 模式）
├─ 老师端 /teacher/*：login、仪表盘、课件列表、新建向导、课件编辑、系统设置（复用现有 settings 面板组件，保存目标改 MySQL）
├─ 学生端：/ 重做为已发布课程库（服务端数据）、/classroom/[id] 播放（readOnly）
├─ API：
│   ├─ /api/teacher/*：auth/login|logout|me、courses CRUD、import-pptx、import-zip、publish、assets/upload、settings、persistence（复用 @openmaic/storage 的 createStorageHttpHandler + 新 MySQL store 实现）
│   ├─ /api/student/courses（列表）、/api/student/courses/[id]（发布快照）
│   ├─ /api/assets/[assetId]：媒体流（Range 支持，模式抄现有 /api/classroom-media）
│   └─ /api/classroom?id=：改造为读 MySQL 发布快照（保留旧 JSON 文件回退，兼容存量）
└─ instrumentation.ts：启动时 ensureDatabase + ensureSchema + seed admin（admin / 首次密码从 env TEACHER_BOOTSTRAP_PASSWORD）
```

**关键复用点（不重造轮子）**：
1. **文档读写**：`@openmaic/storage` 已有 `HttpDocumentStore`/`HttpAssetStore` 客户端和 HTTP 契约（document/asset-http-contract.md），服务端 `createStorageHttpHandler` 是 storage 无关的。只需在应用层实现 `MySqlDocumentStore`、`MySqlAssetStore`（磁盘字节），挂到 `/api/teacher/persistence`，教师会话作为 owner —— 课堂编辑器（`ClassroomSurface`/`EditChromeRoot`/`@openmaic/editor`）无需改动即可读写 MySQL。
2. **PPTX 服务端导入**：`lib/server/agent-runtime/import-pptx.ts`（642 行 worker 版）已有完整先例（80 页/8MB/90s 限制），抽出复用到老师端导入。
3. **zip 导入**：把客户端 `lib/import/use-import-classroom.ts` 的 manifest 解析/校验/媒体重写逻辑移植为服务端版（JSZip nodebuffer → validateStage/validateScene → MySQL + 磁盘）。
4. **AI 生成**：现有 `/api/generate-classroom` job 管线保留，仅把产出从 `data/classrooms/*.json` 改写为 MySQL；生成表单组件迁到老师端新建向导。
5. **系统设置**：`components/settings/*` 面板整体复用挂到老师端，保存从 localStorage 改为 `/api/teacher/settings` → `system_settings` 表；`lib/server/provider-config.ts` 改为 DB → yml → env 三级优先。
6. **媒体链路**：幻灯片 AssetRef 继续用 asset pool id，老师端上传入服务端池；学生端渲染槽位（renderImage/renderVideo）通过只读 HTTP asset 解析为 `/api/assets/<id>`，学生端不再依赖 IndexedDB 媒体。

**Phase 3 老师端课件 UI**
- `app/teacher/courses/page.tsx`（列表：状态筛选/搜索/删除）
- `app/teacher/courses/new/page.tsx`（四入口向导：PPTX 上传、AI 生成表单迁移、zip 导入、空白）

- 生成管线 `lib/server/classroom-generation.ts` 产出改写 MySQL

**Phase 4 学生端瘦身**
- `app/page.tsx` 重做：已发布课程库（`/api/student/courses`）+ 最近学习；移除生成表单、导入按钮、provider 设置入口
- `app/api/classroom/route.ts` 读 MySQL 快照；学生课堂 `readOnly` + `persist:false`（不再写 IndexedDB 文档）
- 服务端媒体 ref 解析接入 `lib/media/` 渲染槽位；设置面板仅保留播放偏好（语速/音量/主题/语言）

**Phase 5 设置后台化**
- `system_settings` 读写 API + `provider-config.ts` DB 优先
- 老师端「系统设置」页（复用现有面板组件，admin 角色可编辑）

**Phase 6 语音预生成（学生开箱即播）**
- 老师端课程详情「批量生成语音」：服务端按 scene actions 调 TTS（服务端配置）→ 入 asset 池（origin='tts'）→ speech action 携服务端 audioRef
- 学生端 speech 播服务端音频；未预生成部分走服务端 TTS 代理实时合成

**Phase 7 收尾**
- i18n（zh/en 起步，走现有 i18next）、`.env.example`/README 更新、vitest 单测（zip 导入解析、repo 层、权限守卫）、Playwright 手动走查两条主路径（老师建课→发布；学生看课→上课）

## 五、风险与对策
- **编辑器与本地 store 耦合深** → 不改课堂/编辑器组件，只换 DocumentStore/AssetStore 接口实现（HTTP 契约已存在）
- **大 JSON 入库** → 快照数 MB 级，MySQL JSON 列与 max_allowed_packet 默认值可承受；必要时分场景行存（scenes 已分行）
- **存量本地课程** → 不迁移；旧 zip 仍可通过老师端导入入库
- **git 里 importer/renderer 的 package.json 已有未提交改动** → 保持不动，不混入本次提交
