# 老师端编辑器：AI 助理（一键生成 + 聊天改课件）实施计划

## 先回答第一个问题：空白课件如何加页（无需改代码）

编辑器已支持多页，入口在**左侧页面缩略图栏（SlideNavRail）**：
- **两页之间的缝隙**（以及第一页上方）hover 时会浮出一个紫色 **`+`** 按钮（[InsertionZone.tsx](G:/ai/OpenMAIC/components/edit/SlideNavRail/InsertionZone.tsx)），点击可选「幻灯片 / 测验」插入新页；
- 缩略图**右键菜单**里有「复制页 / 删除页」（[SlideNavRail.tsx:215-289](G:/ai/OpenMAIC/components/edit/SlideNavRail/SlideNavRail.tsx)）。

注意：`+` 按钮默认不可见，必须把鼠标悬停在缩略图之间的灰色缝隙上才会出现，所以容易误以为"只有一页"。**建议顺手做个小 UX 改进：在缩略图列表末尾常驻一个「+ 新页」按钮**（第一项小改动），避免再有人找不到。

## 总体架构（按用户选定的方向）

两个新功能统一为一套机制：**把 Pro workbench 的 agent runtime 接到老师 MySQL 课件上**，编辑器内嵌一个「AI 助理」聊天面板（复用 `WorkbenchChat`）；「AI 一键生成」按钮 = 面板的快捷入口，向绑定了当前课件的 agent 会话发送生成指令。AI 作为助理自主决策改第几页/新增页/删页（页面级粒度，agent runtime 的 course-tools 已具备该能力）。

### Phase 1 — 服务端：agent runtime 指向老师 MySQL 课件

1. **老师身份接入 owner 解析**
   - [owner.ts](G:/ai/OpenMAIC/lib/server/agent-runtime/owner.ts) 的 `resolveRequestOwnerId` 已预留 `authenticatedOwnerId` 钩子（owner.ts:55-65 注释明确预期接入真实认证）。新增 helper：在 `/api/agent/*` 各路由（sessions / messages / events / cancel / owner-events）里，若 `openmaic_teacher` cookie 有效（`getTeacherSession`），owner 解析为 `teacher:<tid>`，否则维持匿名 cookie。
   - 效果：agent 会话按老师账号隔离；匿名 workbench 用户走原 PG 路径，互不影响。

2. **文档存储 seam 双后端**（关键改动，收敛在单一工厂）
   - [owner-scoped-documents.ts:35](G:/ai/OpenMAIC/lib/server/agent-runtime/owner-scoped-documents.ts) `getOwnerScopedDocumentStore(ownerId)` 按 owner 前缀分支：`teacher:*` → 复用 [course-repo.ts:92](G:/ai/OpenMAIC/lib/server/courseware/course-repo.ts) 的 `documentStoreFor(tid)`（`MySqlDocumentStore` 已实现完整 `DocumentStore` 接口，mysql-document-store.ts:219）；匿名 → 现状 PG。runner.ts:1303/1317 两处调用点自动覆盖。
   - **补齐接口缺口**：
     - `DocumentFolderStore`（createFolder/listFolders/moveDocumentToFolder 等，MySQL 无表）：做一个 no-op 适配器包在 MySqlDocumentStore 外（listFolders → 空列表，移动/重命名为 no-op），满足 `CourseStore` 类型即可；
     - `probeStageAccess`（curriculum-tools.ts:54 直查 PG `stage_meta`）：抽出 `stageAccessProbe` 按 owner 分支，teacher 分支改为 MySQL `document_stages.owner_id = ? AND id = ?` 所有权探测；
     - freshness manifest（PG 触发器维护的 revision）：teacher 分支提供基于 `document_scenes.updated_at` 的最小实现满足接口；编辑器实时刷新不依赖它（见 Phase 3，走会话 SSE checkpoint 事件）。
   - 写路径沿用 PG 路径已有的 `withPlainJsonDocumentWrites` 包装，保持序列化一致。

3. **部署前置条件（需在 README/.env.example 写明）**
   - `NEXT_PUBLIC_PRO_WORKBENCH_ENABLED=true`（构建期）、`OPENMAIC_AGENT_RUNTIME_ENABLED=true`、`DATABASE_URL`（**Postgres**，agent 会话/租约/事件目前唯一后端）、`MODEL_ROUTES` 配好 `maic-agent-driver`。
   - 明确告知：聊天功能引入 Postgres 依赖；未配置时前端探测 `/api/agent/runtime` 为 disabled，隐藏 AI 助理入口（老师端其余功能不受影响）。

### Phase 2 — 编辑器内嵌 AI 助理聊天面板

1. **页面级面板**：[edit/page.tsx](G:/ai/OpenMAIC/app/teacher/(protected)/courses/[id]/edit/page.tsx) 把 `ClassroomSurface` 与新的 `TeacherAssistantPanel` 放进横向 flex（面板可折叠，默认收起为窄条）。`ClassroomSurface` 本体不动。
2. **复用 WorkbenchChat**：面板内按 [WorkspaceChatPane.tsx:182](G:/ai/OpenMAIC/components/workbench/workspace/WorkspaceChatPane.tsx) 的方式包 `WorkbenchCourseNavigationProvider`（activeCourseId/选项指向当前课件）+ `WorkbenchDraftConversationProvider`，挂 `WorkbenchChat hosted`。首条消息懒建会话，复用 [first-message-session.ts](G:/ai/OpenMAIC/lib/workbench/first-message-session.ts) 的 `startConversationWithFirstMessage({ stageId: courseId, existingCourse: true })` 语义，此后每条消息自动携带当前课件的 courseRef，agent 即在当前课件上工作。
3. **SSE 接线**：面板内调用 `useWorkbenchStream(sessionId)`（EventSource 挂 `/api/agent/sessions/:id/events`）。
4. **agent 改动 → 编辑器实时刷新**：新 hook `useTeacherCourseSync(courseId)` —— 收到带 stageId 的 checkpoint 事件后，通过已由 [teacher-bootstrap.ts](G:/ai/OpenMAIC/lib/persistence/teacher-bootstrap.ts) 换接的 `HttpDocumentStore` 重新 `loadDocument(courseId)` 并 setState 回 stage store。**本地有未保存修改时不自动覆盖**，弹 toast 提示「AI 已更新课件，点击刷新」（复用 lib/edit/regen-lock.ts 的锁定思路：agent 正在改的页若处于编辑态，先不替换该页）。

### Phase 3 — 「AI 一键生成课程」按钮（标题旁）

1. **位置**：[CommandBar.tsx](G:/ai/OpenMAIC/components/edit/EditShell/CommandBar.tsx) 标题 `<span>` 后新增可选 `titleAffix?: ReactNode` prop，经 `EditShell/Frame` 透传；[EditChromeRoot.tsx](G:/ai/OpenMAIC/components/edit/EditChromeRoot.tsx) 从新的轻量 context（`EditorAssistantContext`，由老师编辑页 provide，其他入口不 provide → 不渲染）读取按钮。普通 classroom 页面零改动。
2. **交互**：点击弹出小对话框（textarea 课程要求，样式复用 [new/page.tsx](G:/ai/OpenMAIC/app/teacher/(protected)/courses/new/page.tsx) AI tab）→ 提交即向绑定的会话发送指令，如「请为当前课件一键生成完整课程内容：〈要求〉。可新增页面、调整已有页面、生成讲稿」→ 自动展开聊天面板展示 agent 的决策与进度（生成多少页、改了哪些页，在面板里全程可见可追问）。生成与后续调整是同一会话，天然连续。
3. **降级**：agent runtime 未启用时按钮不渲染；纯前端判断（runtime 探测结果缓存到 context）。

## 测试与验收

- 单测（沿用 tests/courseware/backend-flow.test.ts 风格）：owner 解析 teacher/anon 分支；`getOwnerScopedDocumentStore` 分支选择；folder no-op 适配器；MySQL `probeStageAccess`（mock query）。
- `pnpm typecheck` + `pnpm lint` + 现有测试全绿。
- 手动验收路径（需起 MySQL + Postgres + 配好模型）：新建空白课件 → 编辑器末尾「+ 新页」加 3 页 → 点标题旁「AI 一键生成」→ 聊天面板看 agent 追加生成 → 对话「把第 2 页改得更适合初中生，再加一页随堂测验」→ 编辑器自动刷新看到改/增页 → 手动改一页期间 agent 再写 → 出现保护提示。

## 风险与边界（已识别）

- **Postgres 成为聊天功能的硬依赖**（agent 会话存储无 MySQL 实现，移植成本高，不在本期）；纯 MySQL 部署下仅隐藏 AI 入口，其余功能不变。
- agent 写入与老师手动编辑并发：last-writer-wins，用 Phase 2.4 的"脏检查 + 不覆盖正在编辑的页"缓解。
- `MySqlDocumentStore` 与 agent 工具链的接口缝隙（folders/manifest/probe）以适配器补齐，若 runner 还有隐性 PG 依赖，在 Phase 1 联调时逐一处理。
